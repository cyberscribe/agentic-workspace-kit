# What counts as checked

*Copy to `docs/verification.md` and make it true for this team — `/workspace:quick-start` offers to
do that with you. Change the rows to the kinds of work the team actually does, and delete any that
never happen here. Delete this block.*

*When someone says a piece of work is checked, this is what they mean. The closeout's "verify before
recording" step and the close of a project point here, so "checked" means the same thing to every
person and every agent.*

---

| Kind of work | What is checked | By whom or what | Evidence kept |
|---|---|---|---|
| Code | It builds, the tests pass, and the change does what its description says | The test suite, then one reviewer who did not write it | The passing run and the approved pull request |
| Analysis | The numbers reproduce from the named source, and the method is written down | A second person re-runs it from the source | The script or query, and the source's version or date |
| Writing that leaves the team | Every factual claim traces to a source; names, dates and figures are right | The owner, then one reader outside the work | The sources list beside the draft |
| Figures quoted anywhere | Each number matches its source at the date quoted | Whoever quotes it, against the source | The source and its date, next to the figure |
| Guidance an agent reads | It follows the documentation register, and each technical claim matches the current file or code | The standards owner, by pull request | The merged pull request |

A row earns its place when someone would otherwise have to ask "how do we know?". Anything not on
the table is checked by judgement, and saying so is fine.
