# Tests

`bash tests/run.sh` from the kit root. Plain bash; it needs `git`, `jq` and `python3` (3.11 or later,
for `tomllib`). A `claude` binary is optional: the checks that call the real one are reported as
`SKIP` without it, and `AW_REQUIRE_CLAUDE=1` turns that `SKIP` into a `FAIL`, for a release. It builds
every repository it uses under one `mktemp` directory in `$TMPDIR` and removes it on exit; `AW_KEEP=1`
keeps it for inspection.

Each check prints one line — `PASS`, `FAIL` or `SKIP` — with the detail indented under a failure, and
the run ends with a count. It exits non-zero when anything fails. Passing is the bar for every change
to the kit.

## The prelude and the section files

Sections from 12 on live in `tests/sections/NN-name.sh`, one file per section, and are sourced in order
after section 11. Each prints its own heading, prefixes its variables and functions with its number
(`s13_…`), since every section shares one shell, and writes only under `$SCRATCH`. Before section 1 the
prelude builds what they share:

| Name | What it is |
|---|---|
| `KITSRC` | A repository on `main` with one commit whose tree is the kit's working tree, tracked and untracked files alike, modes kept. Every workspace fixture adds the kit from it, so the scripts under test are the working tree's |
| `mkws_kit <dir>` | A new repository with the kit from `KITSRC` at `kit/` and nothing else: where sections 1, 2b and 11 run the engine directly |
| `mkws_min <dir>` | The smallest 3.0 workspace with no setup code: the kit from `KITSRC` at `kit/`, the static tree in `tests/fixtures/ws-min/` (its `dot-` names become dot names), and the git hooks set |
| `mkws <dir> [args…]` | A workspace made with `setup.sh new`, unattended, with the kit from `KITSRC`; setup's output goes to `<dir>.log` |
| `mkws2x <dir>` | A workspace in the 2.2.0 layout, for the migration: the kit at `915c528` as a submodule at `templates/agentic-workspace`, its own installer run, everything committed. It returns 3 in a shallow clone |
| `st_run`, `st_key`, `st_expect`, `st_tree`, `st_bash` | The state-check helpers. `st_key` matches a key by prefix, so per-item keys with `/` and `.` read correctly |
| `$SCRATCH/bin32/bash` | `/bin/bash` first on `PATH`, so child scripts run under bash 3.2 on macOS |
| `gitcount_run <log> <cmd…>` | Runs a command with a `git` that logs each call; `aw_count <log` counts them |
| `cc_gate`, `cc_run` | Claude Code checks: opt-in, a scratch config directory, and one line per run in `$AW_CC_LOG` |

`AW_SECTIONS="13 16"` runs only the named sections, which is quick for work on one of them; a section
that reads another's fixtures brings it along (3 and 9 read 1's).

## What the suite does not reach: Claude Code's plugin registry

The suite never adds, removes or installs a marketplace or plugin in a real Claude Code
configuration, so the re-pointing that `docs/migration.md` describes is checked by hand. One behaviour
to know when doing so: a removed marketplace takes its project-scope enables with it.
`claude plugin marketplace remove agentic-workspace`, with no `--scope`, removes the declaration from
every scope. It rewrites the workspace's `.claude/settings.json`, deleting
`extraKnownMarketplaces.agentic-workspace` and the three `…@agentic-workspace` entries in
`enabledPlugins`, and it uninstalls the plugins; a restart does not bring them back. `--scope user`
limits the removal to the user settings. After any such change, `git diff -- .claude/settings.json`
in the workspace prints nothing when the project scope was left alone.

their own (`CLOSEOUT_*`, `PROJECTS_HOOK_*`, `MEASURE_ALWAYS_LOADED`), documented in their READMEs and
headers. Two `AW_` flags form one family, the flags for a run with nobody at the
keyboard, and the tests set both:

| `AW_HEADLESS_RUN=1` | the projects session-start hook | A headless run, such as an ablation arm: the hook says nothing and records no stamp. `pilot/ablate.sh` sets it on every run it starts |
| `AW_WIZARD_NONINTERACTIVE=1` | `setup.sh`, `lib/wizard.sh` | The wizard runs unattended: every question takes its default. No terminal on stdin has the same effect |

## The word list

Section 6 resolves its list as the hooks do: `$AW_BANNED_WORDS_FILE`, then the `Private word list` of
the workspace around the kit checkout (`.claude/workspace.md`), then
`~/.config/agentic-workspace-kit/banned-words.txt`. The list is kept outside the repository, so no
word on it appears here, in the tests or anywhere else in the kit. One extended-regex alternative per
line; lines starting with `#` and blank lines are ignored. Each alternative is matched as a whole word,
case-insensitive, so a plural or a hyphenated form is caught when the line's own regex allows it
(`widgets?`, `hand-?offs?`). With no list resolved the scan prints one `SKIP` line and the run can
still pass; the probe runs either way. A line that is not a valid extended regex fails the run,
with grep's own message, rather than letting the scan pass unread.

## History

One commit, `d0a56ae` (v1.2), carries attribution trailers and is exempt from section 7 by its full
hash: history is not rewritten for it. Any trailer in any other commit fails the run. The attribution
patterns in `tests/run.sh` are assembled from pieces, so the file is scanned for attribution like any
other.
